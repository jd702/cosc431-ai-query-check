# COSC 431 — AI Query Check

We test whether LLM-generated SQL is **correct, safe, and fast**. We use the Chinook database, questions adapted from Spider, and two free models: Gemini and Llama on Groq.

➡️ **Who does what, and when:** [docs/TEAM_PLAN.md](docs/TEAM_PLAN.md)

## One-time setup (every teammate)

```bash
git clone <our-repo-url> && cd cosc431-ai-query-check
python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python scripts/setup_db.py        # downloads Chinook, builds data/chinook.db + data/chinook_denorm.db
cp .env.example .env              # then paste in YOUR OWN keys (never commit .env)
python -m unittest discover tests # sanity check, should print OK
jupyter notebook
```

API keys are free and need no credit card. Each person uses their own keys.
- Gemini: https://aistudio.google.com → "Get API key"
- Groq: https://console.groq.com → "API Keys"
- Before Deliverable 2, check the current model names and free-tier limits on both sites. Then update `GEMINI_MODEL` and `GROQ_MODEL` in `.env` if needed.

## Where to get questions (Spider)

Spider already contains Chinook-based databases, so adapting its questions is easy:
- **`chinook_1`**: same table names as ours (`Album`, `Artist`, `Invoice`, …). Often needs no changes.
- **`store_1`**: also Chinook, but with snake_case names (`albums`, `invoice_lines`, …). Rename the tables and columns to match ours.

Browse them at https://huggingface.co/datasets/xlangai/spider. Filter `db_id` to `chinook_1` or `store_1`. Record the source in each question's `spider_source` field, and note any wording or SQL changes in `adaptation_notes`.

## Rules we agreed to (from the project guide)
- **One run per question per model.** Notebook 02 caches results, so re-running it won't call the APIs again.
- **Never commit API keys.** `.env` is git-ignored.
- **Grade by result set, not by SQL text.**
- **Only use public data** (Chinook and Spider).

## Deliverable 1 PDF

The submission document is [docs/COSC431_Deliverable1_AIQueryCheck.pdf](docs/COSC431_Deliverable1_AIQueryCheck.pdf), built from LaTeX:

```bash
python scripts/make_latex_appendices.py   # regenerates DDL + question appendices from the data files
cd docs/latex && tectonic deliverable1.tex
```

The appendices are generated, so the PDF can never drift from `data/questions.json`,
`data/gold_results.json` or `sql/normalized_schema.sql`. The Markdown docs stay as the
working copies the team edits.
